## 一、创新性审查（G9 四轴深挖）

### 1.1 问题创新："伦理底线 = GNE 共享约束"是形式化还是隐喻？

**可攻击点**：审稿人可能认为这只是一个**类比/隐喻**（ethics as game），而非真正的新问题形式化——GNE 共享约束是博弈论已知概念（Facchinei & Kanzow 2010），"约束=底线"是诗意映射。

**深层检查**：真正的形式化主张需要三步，当前只完成了两步：
- ✅ 已做：①定义策略空间（t_i, α_i）②共享约束（g_res, g_floor）③均衡概念
- ⬜ 未做：**为什么 GNE 是伦理决策的正确数学结构，而非一种可选建模？**——需要"博弈概念选择论证"：
  - 为什么不是**纳什议价解（NBS）**？NBS 有公理化（帕累托最优/对称性/无关选择独立性）——GNE 的"公平性公理"是什么？（当前靠平衡正则 γ 和 FDBI，非公理化）**这是最可能被攻击的点**
  - 为什么不是 Stackelberg（领导-跟随）？——对等多方 vs 层级
  - 为什么不是合作博弈（核/Shapley）？——合作 vs 非合作

**改进**：新增"建模选择论证"小节——NBS 无法表达共享约束（议价解在可行集外可能）；Stackelberg 预设层级（伦理决策是对等协商）；合作博弈假设可转移效用（原则权重不可转移）——论证 GNE 是唯一能同时表达"多方对等 + 共享底线"的框架。

### 1.2 理论创新：缺可证明定理（最大的理论薄弱点）

**可攻击点**：当前理论 = "形式化 + 映射表"（博弈概念↔伦理意义），缺**可证明的定理**——会被攻击为"理论应用"而非"理论贡献"（对比：A 有边界定理 MV=MC，B 有不可通约性论证——EG 的理论贡献相形见绌）。

**可证明的洞见候选（三定理）**：
| 定理 | 内容 | 证明要点 |
|---|---|---|
| **T1 底线保证** | 若 g_floor 强加于集体向量 v，则任何 GNE 均衡 v* 满足 v* ≥ floor（在凸性+可行性条件下） | KKT 互补松弛 + 约束可行性 |
| **T2 坏均衡排除** | 在鲶鱼扰动 + 底线否决下，违反底线的"伪均衡"不是可存续均衡 | 鲶鱼策略打破共谋不动点；否决使违规点非可行 |
| **T3 公平性界** | 在平衡正则 γ 下，均衡集体向量与各方立场的最小距离有界（议价式公平性） | FDBI 正则的 Lipschitz + 熵正则 |

**改进**：补 T1-T3（至少 T1+T2）——把"底线=共享约束"从形式化升为可证明，正面回应"KKT 收敛≠伦理正确"（T2 给出形式化排除）。

### 1.3 方法统一性：M0/M5 与洞见的弱相关（拼装嫌疑）

**可攻击点**：韧性（M5）和冲突检测（M0）与"伦理底线 = GNE 共享约束"洞见的关系较弱——可能被攻击为"外围工程模块"。

**深层检查**：真正的洞见必要链 = M2 协商（在底线内）→ M3 仲裁（底线执行）→ M4 GNE（底线=共享约束）→ 坏均衡防御（鲶鱼）。M0（检测）/M1（组队）/M5（韧性）是系统完整环节。

**改进**：
- **显式分级**：论文声明"洞见必要环节（M2-M4）vs 系统完整环节（M0/M1/M5）"——不是藏着，而是论证系统完整性为何必要
- **M5 与洞见关联论证**：韧性 = "底线在压力下仍执行"的验证——压力下是否守底线是洞见的直接实证（可把韧性重新定位为"底线的压力稳健性"，强化关联）
- **M0 与洞见关联**：冲突检测（ERS）= "底线可能被突破前的预警"——是底线执行的预防环节

### 1.4 差异化：描述性 vs 规范性未区分

**可攻击点**：NeurIPS 2025（群体投票更功利）是**描述性**（观察 LLM 聚合的伦理倾向）；EG 是**规范性**（设计应然的协商机制）——两者不在同一层，若审稿人认为"你在和描述性工作竞争"会误判。

**改进**：论文明确区分——描述性工作（观察现象）vs 规范性工作（设计机制）；EG 的贡献是规范性 + 可执行，与描述性观察互补而非竞争。

## 二、架构设计审查

### 2.1 鲶鱼角色缺博弈论支撑

**可攻击点**：鲶鱼（catfish）打破合谋是启发式——缺**防合谋博弈/机制设计**的理论依据（合谋下的均衡定义、抗共谋机制的公理）。

**改进**：引机制设计文献（防共谋/策略证明 mechanism）；或形式化"合谋下 GNE 的退化"→ 鲶鱼作为抗共谋扰动的理论角色。

### 2.2 贝叶斯可靠性与伦理底线的耦合风险（公正问题）

**可攻击点**：Beta 可靠性权重 w_i 影响集体向量 v，进而影响底线 g_floor(v)——**不可靠（低权重）智能体的立场对底线影响小**。若患者方被系统判定"不可靠"（如表达能力弱），其原则权重被系统性压低——**违反公正原则**（弱势方声音被压制）。

**改进**：①权重下限（w_i ≥ ε 防压制）②讨论"可靠性≠伦理权重"（可靠性是信息质量，不是道德权重）——需显式分离"信息可靠性"与"立场代表性"。

### 2.3 规则模式的伦理立场来源

**可攻击点**：规则模式是确定性基线，但规则的立场（治疗等级/权重调整逻辑）是硬编码的——**规则本身包含设计者的伦理偏见**；"规则基线可复现"不等于"规则伦理中立"。

**改进**：声明规则是"设计者立场的最小实现"（基线），并讨论规则伦理立场的影响（或提供规则的来源文档）。

### 2.4 治疗强度粒度（0-3）与满意度指标

**可攻击点**：①强度 0-3 粒度粗，可能错过细微权衡（声明为设计参数，但需讨论可扩展性）②**满意度 0.9+ 是好事还是坏事？**——若坏均衡（共谋）也高满意度，满意度不是有效指标（高满意度可能是"均衡太容易"的信号）。

**改进**：①可扩展性讨论（连续强度或更细粒度）②满意度指标的**反例分析**（什么情况下高满意度=坏结果？）+ 与 ERS/底线事件的交叉验证。

## 三、伦理合理性审查

### 3.1 底线否决的权威来源

**可攻击点**：伦理委员会有权 L1 否决其他方——**谁赋予这个权威？为什么伦理委员会高于医生/患者？**（权力不对称的伦理合法性）

**改进**：论证——伦理委员会的角色是"程序性守护者"（守护底线，不替代临床判断）；否决仅对"违反底线"触发，不干预"底线内的自由协商"——权威范围受限（只在底线处），不是全面高于其他方。

### 3.2 资源 cap 的设定者

**可攻击点**：资源 cap 是硬约束——但 cap 由谁设定？（机构/系统利益 vs 患者利益）——资源底线的伦理合法性。

**改进**：声明 cap 为外部输入（机构/政策），论文不替系统设定价值，但需讨论"cap 公平性"（资源分配的公正原则）。

### 3.3 可审计性的边界

**可攻击点**：三段论（LLM 生成）的"可审计格式" ≠ "可审计的正确性"——LLM 三段论可能有幻觉/逻辑错误，"可审计"声称被削弱。

**改进**：①三段论正确性验证（逻辑一致性检查）②声明可审计边界（格式可审计 + 内容需验证）

## 四、理论严谨性审查

### 4.1 GNE 存在性假设

**可攻击点**：GNE 存在性依赖凸性/连续性假设（Facchinei 条件）——J_i 的凸性、约束集凸性是否满足？未声明。

**改进**：显式声明存在性条件（J_i 凸性 + 约束凸 + 连续性）→ 满足则引存在性定理，不满足则说明数值求解的合理性。

### 4.2 指标定义未形式化

- satisfaction：怎么算？（需形式化定义）
- residual_conflict：两两 L1 距离均值——"分歧大=坏"的假设需论证（分歧可能是健康的多视角，不必然是冲突）
- ERS：冲突评分——构成/校准需说明

**改进**：补指标形式化定义 + 每个指标的局限声明。

## 六、总结

```
EG 的创新性与架构的深层问题（非表面）：
  1. 理论贡献缺"可证明定理"（最大的薄弱点——对比 A 的边界定理/B 的不可通约性）
  2. "底线=共享约束"需从"隐喻"升为"形式化"（博弈建模选择论证）
  3. 洞见-模块映射需显式分级（防"全拼装"攻击）
  4. 贝叶斯可靠性↔伦理底线耦合的公正风险（弱势方被压制）
  5. 满意度/冲突指标的局限（高满意度≠好均衡）
修复后：EG 从"强设计+强系统"升级为"可证明理论+完整系统+伦理自洽"
```
