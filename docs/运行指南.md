## 第 1 步：配置文件 `configs/config.yaml`

**默认配置什么都不改就能跑**（rule 模式 = 确定性规则，不需要任何模型/API）。

| 配置段 | 管什么 | 本地默认 | 何时要改 |
|:---|:---|:---|:---|
| `llm.mode` | 基座模式 | `rule` | 用 API/本地模型时改 `api`/`local` |
| `llm.api.*` | 远程 API 地址/密钥/模型 | DeepSeek 示例 | 换服务商/换模型时 |
| `llm.local.*` | 本地模型服务地址/模型名/权重路径 | vLLM 示例 | 部署本地模型时填 `model_path` |
| `datasets.data_dir` | 数据集统一根目录 | 本机 E:\ 路径 | **服务器上必改**（或设环境变量） |
| `datasets.paths` | 逐数据集路径覆盖 | 空 | 各数据集散在不同路径时 |
| `datasets.selected` | 默认用哪些数据集 | 5 个全选 | 只跑部分数据集时 |
| `mane.*` | 协商轮次/阈值 | 已调好 | 一般不用动 |
| `gne.*` | GNE 求解器参数 | 已调好 | 调平衡/收敛行为时 |
| `resilience.*` | 韧性权重/阈值 | 已调好 | 一般不用动 |
| `run.*` | 脚本默认 limit/seed/输出目录 | 50/42/runs | 按需 |

**改配置的三种方式（优先级 配置 < 环境变量 < 命令参数）：**

```bash
# 方式 A：直接编辑 configs/config.yaml（推荐本地）
# 方式 B：环境变量（推荐服务器，不动文件）
set ETHICALGUARD_DATA_DIR=/data/datasets            # Linux: export ...
set ETHICALGUARD_DATASET_PATHS=principlismqa=/data1/PrinciplismQA,medethiceval=/data2/MedEthicEval
set ETHICALGUARD_LOCAL_BASE_URL=http://localhost:8000/v1
set ETHICALGUARD_LOCAL_MODEL=Qwen/Qwen2.5-7B-Instruct
set ETHICALGUARD_MODEL_PATH=/data/models/Qwen2.5-7B-Instruct
set OPENAI_BASE_URL=https://api.deepseek.com/v1
set OPENAI_API_KEY=sk-xxxx
set OPENAI_MODEL=deepseek-chat
# 方式 C：命令参数（单次临时）
python scripts/02_run_mane.py --mode local --limit 5
```

**每个参数是什么意思：**

| 参数 | 含义 | 默认 |
|:---|:---|:---|
| `--config` | 统一配置文件 | `configs/config.yaml` |
| `--datasets` | 用哪些数据集（逗号分隔） | 配置 `datasets.selected` |
| `--limit` | 处理多少个场景 | 配置 `run.limit`（50） |

## 第 3.5 步：韧性评估的两档证据（论文写作用）

**规则模式（rule）＝"一致性基线"，LLM 模式（api/local）＝"完整韧性"。**

| | rule（基线一致性） | api / local（完整韧性） |
|:---|:---|:---|
| 谁在回应压力 | 规则 Agent 的确定性 `_stress_adjust`（硬编码微调） | LLM Agent，提示词含**压力块**（扰动说明+状态偏移），模型真实让步 |
| 报告的 `baseline_only` | `true` | `false` |
| 能否作韧性结论 | ❌ 只证明机制对压力有一致性响应（BSP/C 高是预期） | ✅ 可测"何时放弃原则"：`abandoned`（原则→首个触发放弃的压力）与 `per_perturbation[].agent_abandoned`（谁放弃了哪条） |
| 03_stress 日志 | `[基线一致性]` | `[完整韧性]` |

规则模式韧性数字"太完美"（BSP=1.0、C≈0.96）**不是 bug**：那是确定性基线对压力的不敏感。
论文里把它写成"基线一致性"，与 LLM 模式的真实让步形成对照（比如 BSP 显著下降、
出现 `abandoned: {autonomy: authority}` 这类"在权威压力下放弃自主"的证据）。

### 压力强度网格：从"开关对照"升级为"强度-韧性曲线"

每类压力现在按 `resilience.intensity_grid`（默认 `[0.25, 0.5, 0.75, 1.0]`）**扫多档强度**：
实际注入量 = 基准 delta × 强度（`inject` 按 `Perturbation.intensity` 缩放）。这样每个场景产出：

- `stress_response`（每类压力 × 每档强度）：`consistency` 曲线（强度→一致性衰减）、
  `abandoned_count`（强度→放弃原则数）、`critical_consistency`（C<0.85 的首个强度）、
  `critical_abandonment`（**首次出现放弃的强度 τ**）
- `abandonment_intensity`：原则 → 跨压力类型的最小触发强度（"autonomy 在强度 0.5 就开始被放弃"）
- BSP/C/`per_perturbation` 等主指标取**满档强度**切片，与旧版口径一致

论文表格可直接给：`τ_abandon(autonomy)=0.5 @ authority`，并画"压力强度→一致性/放弃率"曲线。
03_stress 日志会打印全局最小 `tau_abandon`。

```bash
# 默认 4 档网格；想旧版单档行为：--intensity-grid 1.0
python scripts/03_stress.py --config configs/config.yaml --input data_cache/scenarios.jsonl --mode local --limit 10
python scripts/03_stress.py --config configs/config.yaml --input data_cache/scenarios.jsonl --mode local --intensity-grid 1.0 --limit 10
```

**跑完整韧性：**
```bash
# 本地模型（推荐，可控）
python scripts/00_serve_local.py --config configs/config.yaml
python scripts/03_stress.py --config configs/config.yaml --input data_cache/scenarios.jsonl --mode local --limit 10

# 或远程 API
python scripts/03_stress.py --config configs/config.yaml --input data_cache/scenarios.jsonl --mode api --limit 10
```

> 提示：LLM 模式的韧性测试调用量 = 每场景 `1（基线）+ 恢复 + 压力类型数 × 强度档数` 次协商
> （默认 7×4+2 = 30 次）× 每轮 ≤6 轮 × 多方，较大；建议 `--mode local --limit 10` 起步，
> 先用 `--intensity-grid 1.0` 或 2 档（如 `0.5,1.0`）快速冒烟，`temperature: 0.0`（默认）保证可复现。

## 常见问题

| 问题 | 解决 |
|:---|:---|
| `ModuleNotFoundError: yaml` | `pip install pyyaml` |
| 01_prepare 报"未注册的数据集适配器" | `--datasets` 拼写错；可用：principlismqa, medethiceval, vital, medethicsqa, llmevalmed |
| 02/03 报文件不存在 | 先跑 01_prepare，确认 `data_cache/scenarios.jsonl` 生成 |
| API 模式报鉴权失败 | 检查 `OPENAI_BASE_URL/API_KEY/MODEL`，或 config.yaml 的 `llm.api.*` |
| local 模式连不上 | 确认 vLLM 已起（`curl http://localhost:8000/v1/models`），地址/模型名一致 |
| 想只跑一个数据集 | `--datasets principlismqa --limit 10` |
| 03_stress 输出 `baseline_only: true` | 正常：rule 模式只作一致性基线；要测"何时放弃原则"请用 `--mode local/api` |
| 03_stress 的 `abandoned` 通常为空 | rule 模式预期（规则不真放弃原则）。例外：某角色权重本就贴近底线时（如医院管理 B≈0.15），资源/经济压力强度≥0.5 可能触发 `{beneficence: resource}`——属基线口径的边界证据，τ 一般较高，与 LLM 模式的真实让步区分开 |
| 想定位"放弃临界强度" | 用默认 4 档网格看 `stress_response[].critical_abandonment` 与 `abandonment_intensity`；档数越细越准（调用量×档数） |
| 02 结果 `resource_feasible=false` / KKT 很大 | 已修复（P0-1）：仲裁层对 Σρ(t)>cap 强制降级（`arbitration.enforce_resource_cap`），降级后再喂 GNE → 资源约束 KKT 收敛、资源可行率 100%。仍超限只可能是 cap<0 的极端场景 |
| 01 `--report` 分歧率高 | O1 已修复：分歧>0.25 时仲裁改取 LLM 值（语义通道优先）。规则通道的 0 是"未命中"而非"确信为 0"，旧策略分歧取规则值会把 LLM 语义信息全丢（实测 0.741 分歧率时退化为规则通道） |
| 想审计仲裁为什么触发 | 02 日志已打 `仲裁[原因] 裁决t=等级: 理由`（原因=unconverged/satisfaction/resource 组合）；04_eval 打印仲裁原因分布 |
